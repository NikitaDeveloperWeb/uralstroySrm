## Что нужно сделать в следующей сессии

### 1. Исправить конфликты Prisma schema
**Проблема:** В Employee и Brigade одновременно есть строковые поля `skills String` и `skillIds String`, и новые relation поля `skills Skill[]`.

**Решение:**
- Убрать дублирующие поля `skills String` и `skillIds String` из Employee и Brigade
- Оставить только relation `skills Skill[] @relation("EmployeeSkills")` и `skills Skill[] @relation("BrigadeSkills")`
- Обновить API routes brigades и employees, чтобы они не отправляли `skills` как строку

**Файлы:**
- `prisma/schema.prisma`
- `app/api/brigades/route.ts`
- `app/api/brigades/[id]/route.ts`
- `app/api/employees/route.ts`
- `app/api/employees/[id]/route.ts`

### 2. Сгенерировать Prisma Client
**Проблема:** `npx prisma generate` падает с EPERM (файл заблокирован процессом).

**Решение:**
- Перезапустить dev-сервер (Turbopack может блокировать DLL)
- Выполнить `npx prisma generate`
- Выполнить `npx prisma db push` или `npx prisma migrate dev`

### 3. Обновить seed.ts
**Проблема:** В seed.ts используются строковые поля `skills` для Brigade и Employee, но теперь это relation.

**Файл:** `prisma/seed.ts` (строки 34, 122)

**Решение:** Обновить создание brigades и employees для работы с relation skills.

### 4. Проверить TypeScript компиляцию
**Ошибки:**
- `app/api/skills/route.ts` и `app/api/expense-categories/route.ts` — конфликт типов params (Next.js 16 ожидает `Promise<{}>`, а мы используем `{ id: string }`)
- API routes brigades/employees — `skills` конфликтует с relation

**Решение:** После генерации Prisma Client и исправления schema проверить `npx tsc --noEmit`.

### 5. Проверить работу страниц
- Открыть `/skills` — добавить навык, проверить CRUD
- Открыть `/expense-categories` — добавить категорию, проверить CRUD
- Проверить, что навигация работает корректно
