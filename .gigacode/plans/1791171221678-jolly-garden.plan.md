# Миграция БД на Supabase PostgreSQL

## Цель
Полная миграция данных из SQLite (`prisma/dev.db`) в Supabase PostgreSQL без потерь данных и моделей.

## Текущее состояние
- **БД:** SQLite (`prisma/dev.db`) → нужно перенести в Supabase PostgreSQL
- **Prisma schema:** уже настроена на PostgreSQL (`schema.prisma`)
- **Скрипты миграции:** есть, но с ошибками (неправильный порт, устаревшая схема, пропущенные модели)
- **Бэкапы:** 90+ файлов в `prisma/backups/`, последний `backup_2026-10-03T08-46-19.db`
- **Модели:** 40+ моделей (User, Project, Employee, Brigade, Expense, Report и др.)
- **Junction tables:** `_BrigadeSkills`, `_EmployeeSkills`, `_ProjectToSubcontractor`

## Фаза 3: Единый скрипт миграции

### Шаг 3.1: Создать `prisma/migrate-all.ts`
Скрипт обрабатывает таблицы в правильном порядке зависимостей (родители перед детьми):

1. Reference data (без FK): users, clients, skills, expense_categories, hourly_rates, suppliers, contractors...
2. Зависимые: brigades, employees, unit_rates, subcontractors...
3. Projects
4. Project children: material_estimates, project_overheads, completed_works, expenses...
5. Junction tables: _BrigadeSkills, _EmployeeSkills, _ProjectToSubcontractor
6. Custom contractor tables: contractor_contracts, contractor_payments

**Подход:**
- Обычные таблицы → Prisma client `create()` (правильная обработка типов)
- Junction tables → raw SQL (`INSERT INTO ... ON CONFLICT DO NOTHING`)
- Автоматически пропускает `id`, `createdAt`, `updatedAt`
- Обрабатывает boolean (0/1 → true/false) и timestamps (Unix ms → ISO)

**Файл:** `prisma/migrate-all.ts`

### Шаг 3.2: Запустить миграцию
```bash
npx tsx prisma/migrate-all.ts
```

## Риски и замечания

1. **Supabase pooler (порт 6543)** — statement timeout 30 сек. Если миграция зависнет, переключиться на direct connection (порт 5432)
2. **Большое количество записей** — если таблица >10K записей, Prisma `create()` будет медленным. Можно оптимизировать batch insert.
3. **Существующие данные в Supabase** — скрипт использует `ON CONFLICT DO NOTHING` / обрабатывает Unique constraint errors. Если нужна чистая база — нужно сбросить (требует разрешения пользователя).
4. **Бэкап перед миграцией** — рекомендуется создать бэкап `dev.db` перед началом.
