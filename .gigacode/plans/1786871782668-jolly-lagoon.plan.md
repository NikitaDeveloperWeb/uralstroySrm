# План: Разделение "Видов работ" на два таба (Клиенты / Сотрудники)

## Целевое состояние
- Одна страница `/work-types` с табами
- Таблица `UnitRate` получает поле `targetType` ('client' | 'employee')
- Один вид работы = одна запись (например "Обшивка вагонкой")
- Для одного вида работы могут быть две записи: клиент и сотрудник

## Файлы для модификации

### 1. Prisma Schema (`prisma/schema.prisma`)
- Добавить поле `targetType` в модель `UnitRate`:
```prisma
targetType String @default("client") // "client" | "employee"
```

### 2. Типы (`shared/types/unitRate.ts`)
- Добавить `targetType` в интерфейсы `UnitRate`, `CreateUnitRateInput`, `UpdateUnitRateInput`

### 3. API Routes
- `app/api/unit-rates/route.ts` — добавить фильтрацию по `targetType`
- `app/api/unit-rates/[id]/route.ts` — ничего менять не нужно

### 4. Store (`shared/stores/unitRateStore.ts`)
- Добавить параметр `targetType` в `fetchUnitRates`

### 5. Страница (`app/work-types/page.tsx`)
- Разделить на компоненты:
  - `WorkTypesPage.tsx` — страница с табами
  - `WorkTypesList.tsx` — список расценок
  - `WorkTypesModal.tsx` — модалка добавления/редактирования
  - `WorkTypesFilters.tsx` — фильтры (поиск, категория)
- Добавить табы: "Для клиентов" / "Для сотрудников"

## Порядок реализации
1. Миграция базы данных (добавить поле targetType)
2. Обновить типы (`shared/types/unitRate.ts`)
3. Обновить API (фильтрация по targetType)
4. Обновить Store (передача targetType)
5. Рефакторинг страницы на компоненты с табами
