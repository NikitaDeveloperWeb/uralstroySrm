# План: SQLite → PostgreSQL (Supabase) + Деплой на Vercel

## Цели
1. Перенести базу данных с SQLite на PostgreSQL (Supabase)
2. Сохранить все существующие данные
3. Задеплоить приложение на Vercel

---

## Фаза 1: Настройка PostgreSQL

### 1.1 Создать проект в Supabase
- Регистрация на [supabase.com](https://supabase.com)
- Создание нового проекта
- Получение connection string:
  ```
  postgresql://postgres:[PASSWORD]@db.[PROJECT_REF].supabase.co:5432/postgres?sslmode=require
  ```

### 1.2 Обновить Prisma schema
**Файл**: `prisma/schema.prisma`
```prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}
```

### 1.3 Создать .env.example
**Файл**: `.env.example` (новый)
```env
DATABASE_URL="postgresql://USER:PASSWORD@HOST:5432/DATABASE?sslmode=require"
```

### 1.4 Создать локальный .env
```env
DATABASE_URL="postgresql://postgres:[PASSWORD]@db.[PROJECT_REF].supabase.co:5432/postgres?sslmode=require"
```

## Фаза 2: Перенос данных

### 2.1 Установить зависимости
```bash
npm install --save-dev better-sqlite3
npm install -g tsx
```

### 2.2 Создать скрипт миграции
**Файл**: `prisma/migrate-data.ts` (новый)

Скрипт:
1. Создаёт бэкап SQLite (`prisma/backups/pre-migration-[timestamp].db`)
2. Подключается к SQLite (чтение)
3. Подключается к PostgreSQL (запись)
4. Экспортирует все 47 моделей из SQLite
5. Трансформирует поля дат (ISO string → Date)
6. Имортирует в PostgreSQL
7. Выводит сводку

### 2.3 Выполнить миграцию
```bash
# Сначала создать таблицы в PostgreSQL
npx prisma migrate deploy

# Затем перенести данные
npx tsx prisma/migrate-data.ts
```

### 2.4 Верификация
```bash
npx tsx verify-data.js
npx tsx check-salary.ts
npx tsx check-schedules.ts
```

## Фаза 3: Исправление SQLite-специфичного кода

### 3.1 `scripts/list-tables.ts` (строка 4)
Заменить `sqlite_master` на `pg_tables`:
```typescript
// Было:
const tables = await prisma.$queryRaw<any[]>`SELECT name FROM sqlite_master WHERE type='table' ORDER BY name`;
// Стало:
const tables = await prisma.$queryRaw<any[]>`SELECT tablename FROM pg_tables WHERE schemaname = 'public' ORDER BY tablename`;
```

### 3.2 `app/api/backup/route.ts`
Заменить на возврат 410 (file-based backup удалён, Supabase имеет встроенные бэкапы):
```typescript
export async function GET() {
  return NextResponse.json({
    success: false,
    error: 'File-based backups removed. Use Supabase dashboard for database backups.',
  }, { status: 410 });
}
```

## Фаза 4: Настройка Vercel

### 4.1 Обновить package.json
**Файл**: `package.json`
- Добавить в `scripts`:
  ```json
  "build": "prisma generate && next build",
  "prisma:generate": "prisma generate",
  "prisma:migrate": "prisma migrate deploy"
  ```

### 4.2 Создать vercel.json
**Файл**: `vercel.json` (новый)
```json
{
  "buildCommand": "prisma generate && next build",
  "installCommand": "npm install",
  "regions": ["fra1"],
  "functions": {
    "app/api/**/*.ts": {
      "maxDuration": 30
    }
  }
}
```

### 4.3 Создать .vercelignore
**Файл**: `.vercelignore` (новый)
```
prisma/dev.db
prisma/backups/
node_modules/
.next/
```

### 4.4 Настроить переменные окружения на Vercel
Добавить в Vercel Dashboard → Settings → Environment Variables:
- `DATABASE_URL` — connection string к Supabase

### 4.5 Деплой
```bash
npm install -g vercel
vercel login
vercel --prod
```

## Критические риски

| Риск | Решение |
|------|---------|
| `prisma generate` не запущен при билде | Добавить в build script package.json |
| Файловые документы не сохранятся на Vercel | Предыдущая проблема, требует отдельного решения (Supabase Storage) |
| Большие ответы API (>4.5MB) | Пагинация или увеличение лимита в vercel.json |
| Connection pooling на serverless | Для внутреннего инструмента достаточно default |
| Поле `memberIds` в Brigade (JSON string) | Сохранится без изменений |
| Enum `UserRole` (ADMIN/MANAGER) | Убедиться, что значения в uppercase |

## Порядок выполнения

1. `npm install --save-dev better-sqlite3`
2. Обновить `prisma/schema.prisma` (provider + url)
3. Создать `.env` с `DATABASE_URL` к Supabase
4. Создать `.env.example`
5. `npx prisma generate`
6. `npx prisma migrate deploy`
7. `npx tsx prisma/migrate-data.ts`
8. Исправить `scripts/list-tables.ts` и `app/api/backup/route.ts`
9. Обновить `package.json` (build script)
10. Создать `vercel.json`
11. Создать `.vercelignore`
12. Верифицировать локально (`verify-data.js`, `check-salary.ts`)
13. `vercel --prod`
14. Настроить `DATABASE_URL` на Vercel
15. Верифицировать на продакшене
