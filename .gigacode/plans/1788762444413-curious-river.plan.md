# Детальный анализ приложения UralstroyCRM

## 1. Обзор

**Тип:** CRM-система для строительной компании «УралСтрой»
**Стек:** Next.js 16 (App Router), React 19, Prisma, SQLite, Zustand, Zod, TailwindCSS
**Домен:** Управление проектами, сотрудниками, финансами, складами, зарплатами

## 2. Архитектура

### Структура
- **App Router** — страницы в `app/`, API роуты в `app/api/`
- **40+ API роутов** — REST, GET/POST/PATCH/DELETE
- **Zustand stores** (11 файлов) — бизнес-данные
- **React Context** — тема, уведомления, алерты
- **Prisma + SQLite** — 30+ моделей в БД
- **Zod валидация** — централизованные схемы в `shared/lib/validators.ts`

### Ключевые модули
- Проекты (24 компонента) — карты объектов, сметы, транзакции
- Финансы (26 модалок) — расходы, доходы, фонды, авансы, зарплаты, ЕОТ
- Сотрудники/бригады — расписания, навыки, отчеты
- Склад — материалы, движения, поставщики
- Отчёты — сводные, финансовые, PDF-экспорт

## 3. КРИТИЧЕСКИЕ ПРОБЛЕМЫ

### К1. Отсутствие авторизации на API
- **Проблема:** Все эндпоинты открыты, нет middleware
- **Риск:** Любой может читать/изменять данные
- **Файлы:** Все `app/api/*/route.ts`

### К2. Уязвимость токена сессии
- **Проблема:** `base64(user.id:timestamp)` — легко подделать
- **Риск:** Взлом сессии
- **Файл:** `app/api/auth/login/route.ts`

### К3. Утечка паролей в GET /api/users
- **Проблема:** `prisma.user.findMany()` возвращает хеши паролей
- **Риск:** Утечка данных
- **Файл:** `app/api/users/route.ts`

### К4. Разрыв целостности в salary-pay
- **Проблема:** При выплате зарплаты создаётся Expense, но баланс Fund не обновляется
- **Риск:** Рассинхрон данных
- **Файл:** `app/api/salary-pay/route.ts`

## 4. СРЕДНИЕ ПРОБЛЕМЫ

### С1. Дублирование логики дат
- Паттерн `new Date(d.setHours(0,0,0,0))` ... `new Date(d.setHours(23,59,59,999))` повторяется в 5+ файлах
- **Файлы:** `expenses/route.ts`, `advance-reports/route.ts`, `reports/summary/route.ts`, `salary-reports/route.ts`

### С2. Нетипизированные запросы
- `where: any` повсеместно — обход TypeScript
- **Файлы:** `expenses/route.ts`, `advance-reports/route.ts`, `eot-reports/route.ts`

### С3. Inconsistent error handling
- Три разных паттерна обработки Zod-ошибок
- `safeParse` + `issues[0]`, `.parse()` + `'issues' in error`, `handlePrismaError`

### С4. Дублирование схем валидации
- `bonusSchema` и `penaltySchema` определены локально в route-файлах вместо `validators.ts`

### С5. Маппинг статусов "на лету"
- `statusMap` дублируется в `warehouse/route.ts` и `warehouse/[id]/route.ts`
- Статусы 'достаточно', 'мало', 'критически мало' маппятся на 'in-stock' — скрывает реальное состояние

## 5. НИЗКИЕ ПРОБЛЕМЫ

### Н1. SQLite для production
- Не поддерживает конкурентные записи, нет connection pooling
- **Файл:** `prisma/schema.prisma`

### Н2. Нет pagination в API
- Все GET-эндпоинты возвращают ВСЕ записи
- **Файлы:** `warehouse/route.ts`, `employees/route.ts`, `projects/route.ts`

### Н3. `memberIds: String` в Brigade
- Массив сериализован в JSON-строку, нет индексации
- **Файл:** `prisma/schema.prisma`

### Н4. Нет каскадного удаления для Project
- Удаление проекта не удалит связанные FinanceReport, ProjectTransaction и т.д.

### Н5. Нет тестов
- Не найдено ни одного тестового файла

## 6. ПРОИЗВОДИТЕЛЬНОСТЬ

### N+1 запросы
- `reports/summary/route.ts` — 5 полных таблиц с `include`
- `warehouse/route.ts` — `include: { movements, notifications }` для ВСЕХ товаров
- `projects/route.ts` — `include: { brigade, unitRate, materials }` для ВСЕХ проектов

### Индексы
- **Есть:** `ProjectTransaction.date`, `Schedule.date`, `Expense.date`, `AdvanceReport.date`, `EOTReport.date`, `SalaryReport.date`
- **Отсутствуют:** `WarehouseMovement.itemId`, `FundTransaction.fundId`, `Bonus.employeeId`, `Penalty.employeeId`, `ShopReport.employeeId`

### Кэширование
- **Отсутствует полностью** — нет Redis, нет Next.js caching, нет SWR/React Query
