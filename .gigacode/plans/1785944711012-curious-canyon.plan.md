# План: Внедрение API для клиентов

## Контекст

Текущая страница `app/clients/page.tsx` использует `useState` с моковыми данными.
Модель `Client` отсутствует в `prisma/schema.prisma`.
Следуем паттерну `app/api/employees/` для создания API endpoints.

## Требования

1. Добавить модель `Client` в Prisma schema с отношением к `Project`
2. Создать API routes (CRUD) по паттерну `employees`
3. Добавить Zod-схемы для валидации
4. Обновить страницу клиентов для работы с API

---

## Шаг 1: Обновить Prisma schema

**Файл:** `prisma/schema.prisma`

Добавить модель `Client`:
```prisma
model Client {
  id        Int       @id @default(autoincrement())
  name      String
  phone     String
  email     String?
  projects  Project[]

  createdAt DateTime  @default(now())
  updatedAt DateTime  @updatedAt

  @@map("clients")
}
```

Обновить модель `Project` — добавить relation:
```prisma
clientId    Int?
client      Client?     @relation(fields: [clientId], references: [id])
```

Далее выполнить: `npx prisma db push` и `npx prisma generate`

---

## Шаг 2: Добавить Zod-схемы

**Файл:** `shared/lib/validators.ts`

Добавить в конец файла:
```ts
export const createClientSchema = z.object({
  name: z.string().min(1, 'Название обязательно'),
  phone: z.string().min(1, 'Телефон обязателен'),
  email: z.string().email('Некорректный email').optional().nullable(),
});

export const updateClientSchema = createClientSchema.partial();
```

---

## Шаг 3: Создать API routes

### `app/api/clients/route.ts`
- **GET** — получить всех клиентов с проектами (`include: { projects: true }`)
- **POST** — создать клиента (валидация через `createClientSchema`)

### `app/api/clients/[id]/route.ts`
- **GET** — получить клиента по ID с проектами
- **PATCH** — обновить клиента (валидация через `updateClientSchema`)
- **DELETE** — удалить клиента (с проверкой `P2003` — нет привязанных проектов)

Полное соответствие паттерну `employees/`.

---

## Шаг 4: Обновить страницу клиентов

**Файл:** `app/clients/page.tsx`

Заменить `useState` с моковыми данными на `useEffect` с fetch-запросами к API:
- `GET /api/clients` при монтировании
- `POST /api/clients` при добавлении
- `PATCH /api/clients/[id]` при редактировании
- `DELETE /api/clients/[id]` при удалении

UI-компоненты (модалки, поиск, карточки) остаются без изменений — они уже имеют нужную структуру данных.
