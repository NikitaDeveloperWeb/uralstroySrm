# План: Привязка расходов к проектам

## Цель
Добавить опциональную привязку расхода к проекту (объекту). Проект можно выбрать при создании/редактировании, поле необязательное.

---

## ✅ ЗАВЕРШЕНО

### Шаг 1: Привязка projectId к Expense + миграция ✅
- Добавлен `projectId Int?` в модель Expense
- Добавлена связь `onDelete: SetNull`
- Создана миграция `add_project_id_to_expenses`

### Шаг 2: API expenses с проектами ✅
- GET включает project relation
- POST создаёт expense с projectId
- PATCH обновляет projectId
- Создана materialEstimate при добавлении расхода с проектом

### Шаг 3: Типы Expense ✅
- Добавлены `projectId`, `project`, `stage` в интерфейс Expense

### Шаг 4: UI AddExpenseModal ✅
- Добавлен select проектов
- Добавлено поле stage (появляется при выборе проекта)
- projectId передаётся в onSubmit

### Шаг 5: Supplier Materials с projectId и stage ✅
- API `/api/supplier-materials/route.ts` поддерживает projectId, stage, merge логику
- UI на странице supplier-settlements добавляет stage при выборе проекта
- Создана materialEstimate при привязке к проекту

### Шаг 6: Employee Work Reports с projectId и stage ✅
- API `/api/employee-work-reports/route.ts` поддерживает projectId, stage, merge логику
- Создана completedWork при привязке к проекту
- Обновлён Prisma schema: `projectId Int?`, `stage String?`, `onDelete: SetNull`
- Создана миграция `add_stage_to_employee_work_reports`

### Шаг 7: Fix type errors in validators ✅
- Исправлен `updateEmployeeWorkReportSchema`: `.optional()` вместо `.optional().nullable()` для числовых полей
- PATCH endpoint трансформирует validated data для Prisma (undefined → omit, null → null)
- POST endpoint явно конструирует createData объект
- Добавлен `stage` в Expense interface в financeStore.ts и AddExpenseModal.tsx
